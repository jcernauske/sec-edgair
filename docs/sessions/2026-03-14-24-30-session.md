### 7. Gaps and Concerns

**CONCERN 1 — Spec says "25 business terms" but PRIMARY_CONCEPTS maps 25 entries (BT-022 through BT-048, minus BT-025 and BT-026 which are entity terms, not financial metrics).** Count is consistent: 27 BT-IDs in range minus 2 non-financial = 25. Verified correct.

**CONCERN 2 — `sector` field sources from "SIC-to-sector mapping from entity_mappings.sic_code" but `base.financial_facts` does not contain `sic_code` directly.** The implementation will need to join `base.entity_mappings` to get `sic_code`, then apply the SIC_TO_SECTOR mapping. The spec's source column says "SIC-to-sector mapping from entity_mappings.sic_code" which acknowledges this, but the @primary-agent should note this requires a cross-table join, not just reading from financial_facts.

**CONCERN 3 — `fiscal_year_end` sources from `base.entity_mappings.fiscal_year_end` but this field may not exist in the current entity_mappings schema.** The @data-analyst EDA should verify this field exists in entity_mappings before implementation. If it does not, the @primary-agent will need to handle this gracefully (nullable field, so NULL is acceptable).

**CONCERN 4 — `calendar_year` and `calendar_quarter` source from `base.financial_facts` but these fields may be derived, not stored.** The @data-analyst EDA should confirm these fields exist in the base table. If they are not present, the @primary-agent will need to derive them from `end_date` and `fiscal_period`.

**CONCERN 5 — No explicit mention of how to handle the "Informed By" reference.** The spec lists `governance/insights/base-to-consumable-insights.md` as informing the design. This file exists, which is good. The @data-analyst should reference it during EDA.
