## Decisions Made
1. **Bitemporal rules (BASE-BT-*) not SQL-executable** — These rules use `implementation` (Python function references) not `sql`. The runner correctly skips them. They're validated through their existing test suite. This is the right separation: some rules are inherently code-level validation, not SQL queries.
2. **Table reference extraction uses regex with keyword skip list** — Parsing `namespace.table` from SQL is ambiguous (could be `alias.column`). Used a skip list of SQL keywords (`is`, `as`, `on`, etc.) rather than a full SQL parser. Pragmatic for the rule set we have.
3. **Results saved with UTC timestamps** — All execution timestamps use UTC (ISO 8601 with Z suffix) for consistency across environments.
4. **Scorecard overwrites existing files** — Each `scorecard` command regenerates the file rather than appending. The results JSON files provide the historical record.
