## Decisions Made
1. **New table vs evolving financial_facts** — Created a separate `base.conformed_facts` rather than adding columns to `base.financial_facts`. Financial_facts preserves all facts including superseded/competing ones (the "what did SEC filings say?" table). Conformed_facts answers "what is the single best value?" These are distinct responsibilities.
2. **Collision resolution config as governance artifact** — Extracted PRIMARY_CONCEPTS and PRIMARY_UNIT from Python config into `governance/conformation/concept-priority-rules.json`. Makes business rules data-driven and addresses the principal data architect's recommendation.
3. **Lineage preservation via source_fact_id** — Every conformed fact carries a direct FK back to the winning `base.financial_facts.fact_id`, solving the lineage gap the architect identified.
4. **selection_reason + competing_fact_count as audit trail** — Records WHY each fact was selected, not just which one won.
5. **Base = business logic, Consumable = presentation** — This architectural principle drove the entire refactor. Collision resolution, unit filtering, supersession filtering are all "what is truth?" decisions that belong in base.

## Problems Encountered
1. **EDA found 28,849 rows, spec estimated 26,894** — The spec's row count was stale (from before recent data additions). EDA caught this before implementation.
2. **DQ volume rule compound threshold** — BASE-CF-012 used `result >= 25000 AND result <= 35000` which the DQ runner's threshold parser can't handle. Rewrote as a CASE expression returning 0/1.
3. **Overly broad except clause** — Staff engineer caught `except (NoSuchTableError, Exception): pass` in promote.py, which is effectively `except Exception: pass`. Fixed to `except NoSuchTableError: pass`.
