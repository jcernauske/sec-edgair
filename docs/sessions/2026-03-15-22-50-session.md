## Decisions Made
- **Thin shims over deletion**: All old `xbrl_tag_normalization` files became backwards-compat re-export shims rather than being deleted. This ensures zero breakage for any code importing from the old path, including existing tests and DQ rules.
- **JSON format matches spec exactly**: The mapping JSON uses arrays for exact_mappings values `[bt_id, stmt, cat]` and objects for prefix/pattern/heuristic rules, matching the spec's example format.
- **ConceptNormalizer loads from manifest**: `config.py` uses `domain_loader.load_manifest()` to get `hints.concept_mappings` path, falling back gracefully if manifest doesn't exist.
- **Discovery mode returns tier="unmapped" (string)**: When no mappings are loaded, `classify()` returns `tier: "unmapped"` (string) per spec. The backwards-compat `_classify_concept()` wrapper maps this back to integer `3` so old tests pass unchanged.
- **Default normalizer is lazy singleton**: Module-level functions use a lazily-initialized `_default_normalizer` that loads mappings once from the manifest path.
