## Decisions Made
- **TimestamptzType over TimestampType** for `ingested_at` — preserves UTC timezone info, which is the right thing for an audit timestamp. Discovered this creates a `pytz` dependency for DuckDB reads, but that's a small price for correctness.
- **Fixed `append_data` to use explicit Arrow schema** — PyArrow's type inference from Python dicts produces nullable columns and int64 instead of int32. Using `schema_to_pyarrow` from PyIceberg ensures exact type matching. This is an infrastructure improvement that benefits all future specs.
- **Network tests skip by default** — `addopts = "-m 'not network'"` in pyproject.toml. Network tests ran accidentally during first full test run and revealed that SEC EDGAR uses `MICROSOFT CORPORATION` not `Microsoft Corp.` — a useful discovery.
- **Staff engineer approved without changes** — clean code, real tests, proper separation of concerns.

## Problems Encountered
- **PyArrow type inference mismatch**: `pa.table(columns)` inferred all columns as nullable and used int64 instead of int32. First integration test run failed with a detailed schema mismatch error from PyIceberg's compatibility checker. Fixed by passing explicit Arrow schema via `schema_to_pyarrow`.
- **DuckDB needs pytz for timestamptz**: After fixing the schema types, DuckDB's Arrow integration threw `ModuleNotFoundError: No module named 'pytz'` when querying tables with timestamptz columns. Added pytz to dependencies.
- **Network tests ran when they shouldn't**: The `@pytest.mark.network` decorator was present but pytest wasn't configured to skip unknown marks. Tests ran against real SEC EDGAR API and revealed entity name differences (MICROSOFT CORPORATION). Fixed with `addopts` in pyproject.toml.
