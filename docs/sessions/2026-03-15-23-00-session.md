### The story to tell

This should read like a case study / narrative, not a dry architecture doc. The arc is:

1. **The Original Plan** — We were going to do what everyone does: chunk the data, embed it, store vectors, build a RAG pipeline. The build plan had specs for @chunk-strategist, @embedding-engineer, @eval-engineer, @mcp-engineer. We had the whole thing designed.

2. **The Pivot Moment** — The @insight-manager analyzed the actual consumable zone data and said: "This data is structurally hostile to LLM consumption" via embeddings. It's tabular, governed, structured — not documents. RAG is the wrong architecture.

3. **Why RAG Was Wrong For This Data** — Build a compelling comparison:
   - RAG adds a probabilistic retrieval step to data that's already perfectly indexed
   - Embeddings lose the precision of exact financial figures
   - Vector similarity search can't answer "what was Apple's revenue in FY2023" as well as a SQL query can
   - RAG requires infrastructure (vector DB, embedding model, refresh pipeline) that adds complexity without value for structured data

4. **What Was Built Instead** — 7-8 tool functions over DuckDB. Claude calls SQL directly through tools. Every answer is exact, auditable, and traces back through the governance pipeline.

5. **The Irony** — The governance pipeline made RAG unnecessary. The whole point of the project was to make data clean, modeled, and governed. Once you do that, you don't need approximate retrieval — you can query directly. This is the strongest argument FOR the governance pipeline.

6. **What This Means** — Most enterprise AI projects need RAG because their data is messy. If you fix the data first, you might not need RAG at all. The conventional wisdom has the dependency backwards.

### Design

- Include a visual comparison table: RAG Pipeline vs Tool Use Pipeline (side by side)

- Show the actual tool functions that were built (list them with descriptions)
- End with the thesis reinforcement: "The governance pipeline made RAG unnecessary — which is the strongest possible argument for the governance pipeline."
