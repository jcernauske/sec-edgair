## Decisions Made
1. **PyIceberg scan -> Arrow -> DuckDB register** instead of read_with_duckdb (list[dict]). This avoids materializing 125K rows as Python dicts and lets DuckDB run SQL directly against Arrow tables. Much more efficient for the parameterized queries each tool function needs.
2. **Exact match before partial match in metric resolution**. Initial implementation tried ratios first with partial match, causing "Revenue" to match "CapEx-to-Revenue". Fixed by separating exact vs partial matching and trying company_financials exact matches first.
3. **Anomaly flags computed at query time, not stored**. The spec says ~15 rules. Storing them would require a new table and DQ pipeline for zero value. Rules are cheap to evaluate.
4. **System prompt built from real data**. The company roster, metric catalog, and fiscal year range come from querying the actual DuckDB tables at startup. Falls back to a minimal prompt if DB fails.
5. **No Claude API calls in tests**. All 116 tests validate tools, formatting, anomalies, and schemas against real Iceberg data without hitting the API.

## Problems Encountered
1. **Metric resolution partial match false positive**: "Revenue" was matching "CapEx-to-Revenue" because `_detect_metric_or_ratio` tried ratio partial matching first. Fixed by restructuring detection: IDs first, then exact name matches, then partial matches with company_financials priority.
2. **format_yoy_pct zero edge case**: `0.0` is not `> 0`, so no "+" sign was added. Test expectation was wrong ("+0.0%" vs "0.0%"). Fixed the test — zero change shouldn't show a positive sign.
