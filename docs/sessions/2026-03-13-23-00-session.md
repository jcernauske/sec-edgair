## Decisions Made

1. **Governance completeness checklist lives in @governance-reviewer, not a separate file.** The spec template (`docs/specs/_TEMPLATE.md`) doesn't exist yet, so the §12 checklist is defined directly in the governance-reviewer agent. When the template is created, the checklist should be kept in sync.

2. **Mandatory pipeline agents reference the checklist by stating @governance-reviewer checks their output.** Rather than duplicating the full checklist in each agent, the 5 mandatory agents (governance-reviewer, lineage-tracker, dq-engineer, cde-tagger, doc-generator) each state that they "support the governance completeness checklist" and that @governance-reviewer verifies their output.

3. **AI-ready zone agents are lighter-weight as spec directed.** The 4 Phase 5 agents (embedding-engineer, chunk-strategist, eval-engineer, mcp-engineer) have ~50 lines each with role, responsibilities, scope boundaries, audit trail, and key paths — enough to establish their identity without over-specifying formats that will evolve.

4. **OpenLineage event format is fully specified in @lineage-tracker.** Included the complete JSON structure with custom facets for spec references and agent attribution, since lineage is the backbone of the governance story.

5. **@governance-reviewer has explicit severity framework (advisory/changes-requested/rejected).** Three levels with clear meanings and actions, giving the reviewer graduated response options rather than just pass/fail.

6. **Entity resolution includes confidence scoring with a clear cutoff.** Matches below 0.7 confidence are flagged for human review rather than auto-resolved — prevents bad data from propagating silently.
