## Decisions Made

1. **JSON documents, not tables, as the primary AI-Ready shape.** Tables require joins and SQL knowledge. An LLM needs a self-contained document per entity per time period. One read, all context. This is the core architectural decision for the AI-Ready zone.

2. **Company Financial Profile as the #1 data product.** Everything else builds on it. Pre-joining 5 tables into ~340 documents eliminates 80% of query complexity for the most common question type ("tell me about company X").

3. **Template-generated narratives, not LLM-generated.** Pre-writing factual summaries with a template engine (not an LLM) ensures numerical accuracy. The LLM's job becomes synthesis and interpretation, not data retrieval and arithmetic -- which is where LLMs make mistakes.

4. **Anomaly flags as first-class data, not afterthoughts.** Boeing's 346x D/E ratio, Tesla's -132% net margin, Netflix's 497% revenue jump -- these are real data points that need pre-attached explanations. Without caveats, an LLM will present them without context, which is worse than wrong.

5. **Fiscal year alignment is the #1 hidden danger.** Apple FY2024 ends in September, Microsoft FY2024 ends in June, and 15 other companies end in December. An LLM comparing "FY2024 Revenue" across these companies is comparing different calendar periods. Every cross-company comparison in the AI-Ready zone must include temporal alignment warnings.

6. **Ranked 7 specs for AI-Ready zone.** Company profiles first, then metric context, anomaly registry, narratives, comparisons, sector summaries, and embeddings last. Dependencies drive the order.

## Problems Encountered

1. **Large revenue numbers formatted as "B" with no actual value visible.** DuckDB's ROUND function with division by 1e9 was producing results but the display truncated. Not a data problem -- just a display formatting issue in the query output. The actual values are correct in the Iceberg tables.

2. **Goldman Sachs FY2013 amendment with $42.6 trillion max change.** This is a real data point (share-based compensation option counts, not dollar amounts). It's not a data quality issue in our pipeline -- it's a unit-mismatch issue in the amendment tracking that produces misleading magnitude stats when compared to dollar-denominated amendments. The AI-Ready anomaly registry needs to handle this distinction.

3. **GS Net Margin of 279% in FY2024.** Investigated -- this appears to be a legitimate data artifact where Net Income significantly exceeded Revenue for Goldman Sachs, likely due to how "Revenue" is defined for investment banks (which have trading revenue, investment banking fees, etc. that don't all flow through the "Revenue" line item in the same way as operating companies). This is a known limitation of applying standard P&L ratios to financial institutions.
