# SEC EDGAIR — Project Context

## What This Is

SEC EDGAIR is an open source project that proves an AI agent pipeline can take raw, messy, bitemporal financial data from SEC EDGAR and deliver it as a clean, tested, governed, semantically meaningful, AI-ready data product. Agents generate the models and governance artifacts; humans review and approve. Existing tools like SQLDBM and Collibra become the review layer, not the authoring layer.

The name is a dad joke. We're keeping it.

## The Build Plan

The full build plan is in `sec-edgar-data-project-build-plan.md` in this project. Read it before we start anything. Key points:

### Stack
- Python (accessible to data people)
- DuckDB as the processing engine
- Apache Iceberg tables as the output format (portable to S3 Tables, Databricks, Snowflake)
- Claude Code with specialized agents, same workflow as Arteeoo
- Local storage, zero infrastructure — anyone who clones the repo can run it

### Architecture: Raw → Base → Consumable → AI-Ready

**Raw Zone** — Data lands as-is. Agents profile, classify, detect PII, capture source metadata. Nothing is transformed.

**Base Zone** — The real work. Entity resolution, XBRL tag normalization to canonical CDEs, bitemporal modeling (valid time in data + transaction time via Iceberg snapshots), fiscal calendar alignment. Full governance: CDE tagging, OpenLineage lineage, data quality rules, RLS policies, auto-generated data dictionary, agent decision audit trail. All governance artifacts are formatted for Collibra/Alation/DataHub import.

**Consumable Zone** — Use-case-shaped data products: financial comparison dataset, amendment/restatement tracker, point-in-time snapshot queries via Iceberg time travel. Each has a data contract generated by agents.

**AI-Ready Zone** — Semantic embeddings, RAG-ready grounding documents, intelligently chunked context for LLM consumption, evaluation datasets (verified Q&A pairs), quality-aware confidence signals, AI-to-source lineage. Optional MCP server exposing governed data as AI-callable tools.

### Dataset
SEC EDGAR XBRL Company Facts bulk download. 10-20 companies across sectors (big banks, tech, healthcare, retail, industrial, energy). 5 years of filings. Naturally bitemporal — filings have valid periods and transaction times, amendments create multiple versions of the same fact.

### Agents

| Agent | Role |
|-------|------|
| `@data-profiler` | Schema detection, statistical profiling, anomaly detection |
| `@pii-scanner` | PII detection and classification |
| `@semantic-modeler` | Proposes dimensional models from raw data |
| `@entity-resolver` | Company identity resolution across CIKs, names, tickers |
| `@cde-tagger` | Maps fields to canonical Critical Data Elements |
| `@temporal-modeler` | Designs and implements bitemporal schema with Iceberg |
| `@dq-engineer` | Generates and runs data quality rules |
| `@lineage-tracker` | Captures transformation lineage in OpenLineage format |
| `@governance-reviewer` | Reviews governance metadata for completeness — the "FAANG staff engineer" of data |
| `@doc-generator` | Auto-generates data dictionaries, catalogs, data contracts, grounding documents |
| `@embedding-engineer` | Generates semantic embeddings, manages vector index |
| `@chunk-strategist` | Designs intelligent chunking for LLM consumption |
| `@eval-engineer` | Generates evaluation Q&A pairs from governed data |
| `@mcp-engineer` | Builds MCP server exposing governed data as AI-callable tools |

### Workflow Per Feature/Transformation
1. Write a spec (what transformation, why, expected input/output)
2. Spec reviewed by `@governance-reviewer`
3. Implementation by appropriate agent
4. `@lineage-tracker` logs the transformation in OpenLineage format
5. `@dq-engineer` generates and runs quality tests
6. `@cde-tagger` updates CDE mappings
7. `@doc-generator` updates documentation, data dictionary, and data contracts
8. All agents log decision rationale to audit trail

### Key Demos to Build Toward

**End-to-End Governance Walkthrough:** Pick a single field — JPMorgan's Q3 2024 Revenue — and show full lineage back to raw XBRL, CDE mapping, quality rules, classification, bitemporal history via Iceberg snapshots, agent decision audit, and data dictionary entry. All generated by agents, reviewed and approved by humans.

**"AI-Ready" Demo:** Show an AI querying the governed data via grounding documents or MCP server, getting a correct answer with full lineage from the AI's response back to the raw SEC filing. The audit trail a regulator wants to see.

### The Thesis

"Everyone says 'you can't do AI until you fix your data.' OK — I fixed the data. Here's what AI-ready actually looks like." The project demonstrates the full lifecycle from raw messy data to governed, AI-ready output, built by one person with AI agents.
